# nice-tools 첫 버전 설계

## 목적과 완료 기준

내부망에서 사용할 도구를 추가해 나갈 Python 웹 프로젝트를 만든다.
첫 도구는 사용자 PC에서 선택한 두 디렉토리의 텍스트 파일 비교다.
접을 수 있는 왼쪽 메뉴에서 도구를 선택하고 같은 화면 안에서 실행한다.

완료 기준은 폴더 선택부터 서버 비교, 결과 표시까지 실제로 동작하는 것,
옵션별 자동 테스트가 통과하는 것, 실행 방법과 재사용 클라우드 설정이 준비되는 것이다.

## 기술과 구성

- Python 3.12 이상, FastAPI, Uvicorn.
- 화면은 기본 HTML, CSS, JavaScript로 구현한다. 외부 CDN, 웹 폰트, 프런트엔드 빌드 도구는 사용하지 않는다.
- FastAPI가 정적 화면과 비교 API를 함께 제공한다.
- 비교 함수는 HTTP 처리와 분리해 독립적으로 테스트한다.
- 데이터베이스나 외부 서비스, API 키는 필요하지 않다.
- 이후 도구는 메뉴 항목, 화면, 필요한 서버 기능을 추가하는 방식으로 확장한다.

## 화면과 사용 흐름

1. 왼쪽 메뉴에 프로젝트 이름, 접기/펼치기 버튼, 디렉토리 텍스트 비교 항목을 둔다.
2. 왼쪽 폴더와 오른쪽 폴더를 각각 브라우저의 디렉토리 선택기로 선택한다.
3. 선택한 폴더 이름과 파일 수를 표시한다.
4. 줄 정렬, 공백 무시 체크박스와 앞/뒤 무시 글자 수 입력을 조정한다.
5. 비교 버튼을 누르면 진행 상태를 표시하고 중복 실행을 방지한다.
6. 결과에는 상태별 파일 수와 상대 경로별 결과 표를 표시한다.
7. 실패 시 원인을 화면에 표시하고 폴더나 옵션을 수정해 재시도할 수 있게 한다.

UI는 한국어로 제공한다. 접기 버튼과 입력 요소는 키보드로 조작할 수 있고
버튼의 펼침 상태와 진행/오류 상태를 보조 기술에 전달한다.
사용자 파일명과 오류 메시지는 HTML로 해석하지 않고 텍스트로 표시한다.

## 폴더와 파일 처리

- 디렉토리 선택에는 `webkitdirectory`와 `File.webkitRelativePath`를 사용한다.
- 두 폴더의 최상위 이름은 제외하고 하위 상대 경로가 같은 파일끼리 비교한다.
- 폴더 이름이 달라도 `sub/example.txt`끼리 짝지어진다.
- 숨김 파일과 하위 디렉토리 파일도 브라우저가 선택 목록에 제공한 경우 포함한다.
- 비어 있는 디렉토리는 브라우저 파일 목록에 나타나지 않으므로 비교하지 않는다.
- 확장자로 제외하지 않고 선택된 모든 파일에 UTF-8 텍스트 해석을 시도한다.
- UTF-8 BOM은 허용한다. 잘못된 UTF-8이나 NUL을 포함한 파일은 읽기 오류로 표시한다.
- 한쪽에만 존재하는 파일은 별도의 존재 상태로 표시한다.
- 상대 경로의 중복, 절대 경로, 경로 이탈 표현은 요청 오류로 처리한다.

## 비교 규칙

기본값은 줄 정렬 끄기, 공백 무시 끄기, 앞/뒤 무시 글자 수 각각 0이다.

각 파일을 줄 단위로 나눈다. CRLF, LF, CR 줄바꿈은 동일하게 처리하고
마지막 줄 끝의 줄바꿈 유무는 비교 결과에 영향을 주지 않는다.
파일 중간의 빈 줄은 유지한다.

각 줄에 다음 순서를 적용한다.

1. 원래 줄의 앞과 뒤에서 지정된 수만큼 글자를 제외한다.
2. 공백 무시가 켜지면 줄 안의 공백 문자(스페이스, 탭, 기타 Unicode 공백)를 제거한다.
3. 줄 정렬이 켜지면 변환된 줄들을 Unicode 코드 포인트 순으로 정렬한다.
4. 변환된 줄 목록을 비교한다.

글자 수는 바이트가 아닌 Unicode 코드 포인트 수다.
앞/뒤 무시 수의 합이 줄 길이 이상이면 그 줄은 빈 문자열이 된다.
줄 정렬은 중복 줄을 보존한다. 공백 무시만으로 빈 줄을 삭제하지 않는다.
옵션 값은 음수가 아닌 정수만 허용한다.

파일 상태는 동일, 차이, 왼쪽만, 오른쪽만, 읽기 오류다.
동일/차이는 옵션 적용 후의 결과를 의미한다.
결과는 상대 경로 기준으로 정렬하고 전체/상태별 개수를 함께 제공한다.

## API와 자원 처리

`POST /api/compare`에 두 파일 집합, 각 집합의 상대 경로 목록,
비교 옵션을 multipart 요청으로 보낸다. 응답은 요약과 파일별 상태의 JSON이다.

비교는 메모리에서 수행하고 사용자 파일을 프로젝트나 영구 저장소에 보관하지 않는다.
업로드 처리 과정에서 프레임워크가 사용하는 임시 파일은 요청 후 닫아 정리한다.
첫 버전의 업로드 한도는 양쪽 합계 1,000개 파일, 요청 전체 50 MiB,
개별 파일 10 MiB다. 한도를 넘으면 분명한 오류를 반환한다.
브라우저도 파일 수와 크기를 검사하지만 서버에서 다시 검증한다.

기본 실행은 루프백 주소에서 시작하고 내부망 배포 시 바인딩 주소를 실행 옵션으로 지정한다.
첫 버전에는 로그인, 사용자 계정, 비교 기록, 원본 파일 다운로드,
서버 경로 접근, 줄 단위 차이 뷰어를 넣지 않는다.

## 검증

- 비교 함수: 동일/차이, 한쪽만 존재, 상대 경로, 빈 파일/빈 줄,
  BOM/줄바꿈, 줄 정렬과 중복 줄, 공백, 앞/뒤 글자 제외,
  Unicode, 옵션 조합, 읽기 오류를 검증한다.
- API: 실제 multipart 업로드, 요약/상태, 잘못된 옵션/경로,
  파일 수/크기 제한, 오류 후 재시도를 검증한다.
- 화면: 폴더 선택, 옵션 전달, 결과 표시, 메뉴 접기/펼치기를 브라우저에서 확인한다.
- 실제 Uvicorn 서버에 화면 요청과 대표 비교 요청을 보내 실행 준비 상태를 확인한다.

## 개발과 클라우드 환경

의존성은 저장소 안의 `.venv`에 설치하고 설치 목록의 버전을 고정한다.
`.gitignore`로 가상 환경, 캐시, 생성물을 제외한다.
README에 설치, 개발 실행, 테스트, 내부망 배포 방법과 인코딩/업로드 한도를 적는다.

기존 체크아웃을 사용하고 Git worktree를 만들지 않는다.
검증한 설치 스크립트와 서버 시작/준비 확인 명령을 클라우드 환경 설정 초안에 저장한다.
스냅샷에서 프로세스가 살아 있을 것으로 가정하지 않는다.
첫 커밋과 `main` 브랜치를 준비하고 원격 반영 여부를 명확히 보고한다.
