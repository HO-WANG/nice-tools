# SAP IQ SELECT export

Add a fourth local tool to nice-tools that verifies an IQ connection using the PC's installed 64-bit SAP IQ/SQL Anywhere ODBC driver, runs one SELECT (including SELECT CTEs), and streams the complete result into a local text file. pyodbc and application assets remain inside the single Windows EXE; proprietary ODBC drivers remain a PC prerequisite. No IQ driver/server/credentials exist in cloud, so report that real-server verification remains external.

The connection form accepts host, port (2638 default), optional database/server name, account, password and an installed IQ driver (automatic recommendation). Exclude ASE/SQL Server/FreeTDS from automatic IQ selection. Return safe stage/SQLSTATE diagnostics without native error text or credentials. Credentials stay in memory and reach owned workers over stdin only, never CLI arguments, files, logs or browser storage. Connection verification closes its native connection; each export opens its own isolated worker connection, so cancellation can terminate a blocked native driver and its owned process tree. Do not represent an idle session as an open native DB connection.

Use explicit SELECT-only validation before launching work, reject scripts, SELECT INTO and write/execute statements outside quoted text/comments, request ODBC read-only access and roll back on close. These client controls do not replace DB permissions for side-effecting server functions. Stream fetchmany batches, preserve numeric precision and complete results, and never log SQL or row values.

Default text settings: EUC-KR, field `|`, row `\n`, no header. Allow UTF-8/CP949/EUC-KR, explicit field/row terminators and optional header. Character text uses BCP conventions (NULL empty, empty text NUL), exact decimal/date text and binary hex. Reject unsupported or unencodable values and embedded separators/NUL rather than corrupting records. Preserve existing destination files and publish only successful exports atomically; cancelled/failed jobs remove only their owned stage. Default output folder is beside the EXE (repo root for source), `iq-result.txt` with `_1`, `_2` collisions, no subdirectories. A native folder picker changes the server-owned session path; API does not accept arbitrary output paths.

Use the existing bounded transfer dispatcher and owned Windows suspended-process/job primitives, plus ExportReservation and atomic publication, without changing ASE behavior. Exports run in background; show phase, rows, bytes, elapsed time, throughput, final path, and cancel. One IQ export per IQ session; app transfer worker maximum remains five. Connection checks/pickers use owned workers. Shutdown/disconnect/cancel must prevent late publication and reap workers.

HTTP contract (all responses no-store; same loopback/origin checks, mutation header `X-Nice-Tools: iq`):

- GET `/api/iq/status`: `{available,module_available,drivers:[name],driver,detail,export_directory}`. List compatible installed IQ/SQL Anywhere driver names, never ask for an ODBC DSN.
- POST `/api/iq/connect`: `{host,port,database,server_name,user,password,driver}` -> `{session,driver,version,export_directory}`. Optional database/server_name/driver strings may be empty. Password is cleared after attempt. No autosave in this first IQ version.
- POST `/api/iq/pick-directory`: `{session}` -> `{cancelled,path?}`.
- POST `/api/iq/jobs`: `{session,sql,filename,options:{encoding,field_terminator,row_terminator,include_header}}` -> `{job}`.
- POST `/api/iq/job` and `/api/iq/cancel`: `{session,job}` -> `{job,state,phase,rows,bytes_written,elapsed_seconds,rows_per_second,path,message,result?}`; state running/succeeded/failed/cancelled, phase queued/connecting/querying/writing/done/cancelling. Result contains rows,bytes_written,columns,path,elapsed_seconds,rows_per_second. Numeric fields may start at zero, rate may be null.
- POST `/api/iq/disconnect`: `{session}` -> `{ok:true}`.

Do not expand profile storage, JDBC/Java/native client bundling, server-side file extraction or arbitrary SQL execution. Keep other three tools, unlimited comparison inputs and all current ASE behavior intact.
