# SAP IQ export implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Stream SAP IQ SELECT results into local EUC-KR pipe text from the existing single-EXE tool suite.

**Architecture:** Isolated IQ ODBC workers verify connections and export into parent-owned staged files. The server owns session credentials, folder selection and publication; the browser owns only opaque tokens and text controls. Reuse existing safe process, dispatcher and publication primitives while keeping IQ modules separate.

**Tech Stack:** Python 3.12, bundled pyodbc 5.3.0, FastAPI, existing vanilla HTML/CSS/JS, PyInstaller; registered IQ ODBC driver external.

**Spec:** `docs/superpowers/specs/2026-10-15-iq-export.md` (including exact API).

## Global Constraints

- One Windows nice-tools.exe; no runtime Internet/CDN or bundled proprietary drivers.
- Existing ASE / comparison / Jasypt behavior preserved; no worktrees.
- Never persist credentials or SQL/results in diagnostics or browser storage.
- Streaming full results; strict encoding; atomic non-overwrite publication and cancellation ownership.

## Review Focus

- Driver names and connection values containing braces/semicolons: preserve ODBC values and reject injection.
- SQL literals/comments/CTEs: accept valid SELECT text while rejecting scripts and writes.
- NULL/empty/Unicode/Decimal/LOB-sized values: serialize predictably or fail without final publication.
- Cancel/disconnect/shutdown during native execute or publication: terminate owned workers and preserve unrelated files.
- Abandoned connection/picker HTTP calls and stale browser responses: clean up eventual sessions and never restore stale paths/results.
