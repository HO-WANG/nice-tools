# ASE BCP Implementation Plan

> **For agentic workers:** Use isolated file ownership and test-first implementation. Root integrates and performs a whole-change independent review.

**Goal:** Add a local ASE browser and character BCP IN/OUT tool to the single Windows EXE.

**Architecture:** Embedded FreeTDS DB-Library runs in an isolated worker of the same executable. Memory-only sessions and single-use reviews control background transfers. The browser selects real PC files through native dialogs.

**Tech Stack:** Python 3.12, FastAPI, ctypes, FreeTDS 1.5.19, vanilla HTML/CSS/JS, PyInstaller.

**Spec:** `docs/superpowers/specs/2026-10-13-ase-bcp.md`

## Global Constraints

- Exactly one Windows 10/11 x64 `nice-tools.exe`, with no runtime Internet requirement.
- Character BCP only; IN appends; views OUT only; procedures browse-only.
- No fixed file byte caps; no credential persistence or credential arguments.
- Native Windows EXE checks are required; real ASE compatibility remains unverified without a server.

## Review Focus

- A changed file/schema after review must be rejected before IN.
- Cancel/error must preserve the existing OUT destination and disclose partial IN batches.
- Non-ASCII file paths and CP949 must work without narrowing paths to the Windows code page.
- SQL identifiers and native errors must not expose credentials or permit injected SQL.
- Delimiter boundaries, large fields and decimal precision must not silently truncate data.

### Task 1: Native library and bridge

**Files:** `scripts/build_ase_native.ps1`, `packaging/ase_native_patches.py`, `nice_tools/ase_native.py`, `tests/test_ase_native.py`.
**Interfaces:** `native_status() -> dict`; `run_operation(payload: dict, emit=None) -> dict`, operations databases/owners/objects/columns/transfer. Column metadata uses position/name/type_id/type_name/length/precision/scale/nullable/identity. Transfer consumes reviewed columns, path and normalized options.

### Task 2: File preflight and worker

**Files:** `nice_tools/ase_files.py`, `nice_tools/ase_worker.py`, `nice_tools/ase_picker.py`, corresponding tests.

Worker stdin is one JSON object; stdout is JSON-lines progress/result/error.
